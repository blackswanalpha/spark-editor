# 0.6.0 — 2026-08-31

Open a folder and it becomes a project. Quit, relaunch, and you are back where you stopped.

See `CHANGELOG.md` for the full entry.

- **A project is an opened folder.** No naming step, no setup, and nothing written into your directories — no `.spark/`, no dotfile, no lock. Opening a folder creates or touches its record; **File → Switch Project…** lists them most-recent-first, with in-place rename and remove. Removing a project drops the record only; the folder on disk is untouched.

- **Continue where you stopped.** The most recently opened project is restored silently on launch: its open tabs in the order you left them, each on the right editor surface with its caret and scroll offset; the tab that was in front; the explorer's root, expanded directories, hidden-file toggle and selection; terminal tabs rooted at their previous working directory; and the terminal panel, sidebar and status-bar layout. Files that were deleted since last quit are dropped with a single notification rather than an error per file.

- **Each project keeps its own state.** Opening a `.txt` as code in one project does not change how it opens in another. Switching projects flushes the outgoing one before anything is torn down, so nothing leaks between them.

- **Only paths are stored, never your content.** A restored tab reads its text from disk, which is the same guarantee the rest of the editor makes. Terminal tabs come back as fresh shells at the old working directory — there is no process on the host to reattach to, and scrollback is not persisted. Everything lives in `projects.json` in the app-data directory; deleting it costs you your restore state and nothing else.

- **The empty state is about projects now.** "New document" is gone. The cards are **New project…**, **Switch project…** — with a count of remembered folders — and **Open file…**, over a Recent projects list showing each folder's path and how many tabs come back with it. With a project already open the heading reads "No files open in *project*" instead of greeting you as a first-time user.

- **The splash stops naming a file that never existed.** Its stages read "reading projects.json…" and "restoring workspace…", over work that really happens, and it now holds until restore has finished rather than dismissing on a timer alone.

## Fixed

- **sparkEditor did not run in a browser at all.** The title bar's title-sync effect called `getCurrentWindow()` unguarded; outside Tauri that throws on `window.__TAURI_INTERNALS__.metadata`, and the optional-call syntax could not catch it, so the entire shell crashed on mount under `npm run dev`. All four window calls are now gated.

- **The close button skipped the unsaved-changes prompt.** It called `window.close()` directly, so quitting the ordinary way — the titlebar X — bypassed the dirty-buffer guard entirely. It now routes through the shell like every other close path, which is also what lets the final workspace snapshot be written.

- **`Open Recent` opened the command palette**, which contains no files. It is now **Open Recent File** and opens the sidebar's Recents tab.

- Removed three bridge stubs (`getAppState`, `setAppState`, `windowSetTitle`) that invoked Rust commands which were never implemented.
