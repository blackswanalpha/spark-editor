# 0.7.2 — 2026-09-01

`Shift+Tab` actually reaches the shell this time, and the terminal stops leaking shells between windows and projects.

See `CHANGELOG.md` for the full entry.

- **`Shift+Tab` was never an app shortcut — it was an unhandled key.** WebKitGTK names `Tab` and `KP_Tab` but not `ISO_Left_Tab`, which is the keysym `Shift+Tab` actually produces, so the press arrived as `key: "Unidentified"` with only `code`/`keyCode` saying Tab. The terminal dropped it as IME noise, which meant nothing was sent to the shell *and* nothing was cancelled — so the webview ran its own default and moved focus to the previous tab stop. 0.7.1 read that focus move as the engine ignoring `preventDefault` and rearranged the tab order to compensate; the diagnosis was wrong, and both workarounds are gone. The key is recognised now, `CSI Z` reaches the shell, and cancelling the press keeps the keyboard where it was.

- **Clicking away from the terminal right after typing works.** 0.7.1's other workaround pulled focus back to the shell on any focus loss within 150 ms of a keystroke, so typing a command and clicking straight into the editor left the keyboard on the terminal.

- **Popping the terminal out moves your shells instead of killing them.** The panel used to keep its sessions and respawn the lot the next time it opened: every running program died on the way across, and both windows ended up holding shells. Running sessions are now handed to the new window and keep running; a tab whose shell had exited is restarted there.

- **A pop-out window closed from its title bar no longer leaves its shells running.** Closing the window destroys the webview without unmounting anything, so nothing ever ended those sessions — they held a pty, a writer and 5000 lines of scrollback each until the app exited.

- **Terminals no longer follow you between projects.** Switching or closing a project left the previous project's shells open, and the next autosave wrote them into the new project's saved workspace.

- **Pasting into a busy shell no longer freezes the window.** Writes to the pty ran on the UI thread and block once the terminal's input queue fills — about 4 KB — so a paste into a shell whose program was not reading stopped the whole app until it did. Closing, restarting or elevating a shell stalled the UI the same way while the old one was killed and reaped.

- **A resize or a scroll no longer blanks the screen.** Frames are numbered under one lock but were sent after releasing it, so a full repaint could arrive behind a delta built after it; the renderer discarded the repaint and painted the delta onto a grid of the wrong shape.

- **"Open in Terminal" on a folder whose shell has exited opens a new one** rather than landing you in the dead tab.

- **Terminal tabs are reachable from the keyboard.** `←`/`→` move between them, `Home`/`End` jump to the ends, `Delete` closes one, and focus follows the tab that takes over when you close the focused one.

- **A terminal opened on a collapsed folder starts in that folder**, not its parent.

- **A terminal panel restored from your last session no longer steals the keyboard at startup.**
