# 0.7.0 — 2026-09-01

Copy and paste work in the terminal, and the explorer pane resizes the pane rather than only its boundary.

See `CHANGELOG.md` for the full entry.

- **Selecting terminal text produces the text you selected.** The screen is painted as absolutely positioned spans off measured cell metrics, so the browser's own selection returned every row concatenated with no line breaks — copying three lines pasted one. Selection is now modelled in grid coordinates and the text is rebuilt from the same rows that were painted. Drag to select with a highlight that follows the grid, double-click a word (paths and URLs count as one), triple-click a line, or **Select all** from the right-click menu.

- **Paste has a keyboard again.** `Ctrl+V` used to encode `^V` — readline's quoted-insert — *and* suppress the webview's own paste, so nothing could be pasted with the keyboard at all; `Ctrl+Shift+V` fell through to nothing. Paste is now `Ctrl+V`, `Ctrl+Shift+V`, `Shift+Insert`, middle-click or the menu. Copy is `Ctrl+Shift+C`, `Ctrl+Insert` or the menu. `Ctrl+C` stays SIGINT, which is the whole reason terminals moved copy onto a second modifier.

- **The clipboard was never granted.** `clipboard-manager:default` grants no permissions in Tauri v2, so the plugin was installed and unusable. Reads and writes go through the OS plugin now — WebKitGTK has no `navigator.clipboard.readText` — with the web APIs as fallback.

- **Clicking inside a full-screen program does something.** A TUI that turns mouse reporting on owns the pointer, so the terminal declined to select — but it handed the program nothing either, leaving menus and buttons unreachable and no way to copy out of one. Presses, drags and releases are encoded as xterm mouse reports; hold Shift to select instead, as in every other terminal.

- **Non-US keyboards can type their symbols.** AltGr is reported as ctrl+alt, and the meta rule turned the `@` on a German layout into `ESC @`. IME composition was typed twice. A modified function key sent the unmodified sequence, so `Shift+F3` silently did `F3`.

- **The explorer pane resizes its contents.** The sidebar was pinned to a fixed 260px width — the cross axis of a column flex container — so dragging the handle moved the boundary while the contents stayed put. Dragging is also smooth now: the width goes straight onto the element and commits to state once on release, instead of re-rendering the whole shell and writing `localStorage` sixty times a second.

- **"Show explorer" works.** The reveal button sits inside the resize handle, whose pointerdown starts a drag and captures the pointer, so the button's click never arrived.

## Fixed

- **A shell you exited leaked.** Its session stayed in the host's table for the life of the window, holding the pty file descriptor, the writer and a vt100 parser with 5000 lines of scrollback — and `pty_list` reported shells that no longer ran.

- **Idle terminals kept the CPU awake.** The frame pump woke every 8ms for the life of every session — 125 times a second per open tab whether or not anything had happened. It blocks on a condition variable now.

- **Frames were decoded once per tab.** Every terminal registered its own listener and threw away what was not its own; the window listens once and fans out by session id. Killed shells are reaped on shutdown instead of left as zombies.

- **A paste could break out of bracketed paste.** An `ESC[201~` inside copied text ended paste mode early, so the rest ran as typed input — a paste that runs a command the user never saw.

- **Long file names ran past the explorer.** Tree rows had no `min-width: 0`, so as flex items they refused to shrink below their text and pushed out of the pane instead of truncating. Indent is capped against the row width, and the header wraps rather than crushing the folder name to `PLAN…`.

- **The pane could be dragged over the editor.** The clamp knew only its own maximum, not the window; it now reserves the rail and 320px of editor.

## Known issues

- **`Shift+Tab` moves focus out of the terminal.** WebKitGTK traverses focus on Tab even when the key press's default is cancelled, so the keyboard lands on the panel's own buttons. The key does reach the shell, and the terminal now takes focus back, but the traversal itself is the engine's.
