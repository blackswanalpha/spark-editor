# 0.5.0 — 2026-08-30

The terminal becomes scrollable — in a shell and inside a full-screen program — and stops painting half of what it is given.

See `CHANGELOG.md` for the full entry.

- **Scrolling works inside a full-screen program.** A TUI (Claude Code, `vim`, `less`, `htop`) runs in vt100's alternate screen, and that grid is constructed with **zero scrollback** — `pty_scroll` was a guaranteed no-op because there was no history to move through. Real terminals do not scroll here either; they hand the wheel to the program. Spark did neither, which is why the wheel appeared dead in exactly the case people noticed. A wheel notch now has three destinations, chosen from what the program asked for: an xterm mouse report (buttons 64/65, SGR or the legacy encoding) when mouse reporting is on, arrow keys when the alternate screen is up without it — xterm's `alternateScroll`, which is what makes `less` and `man` scroll — and the scrollback viewport otherwise. Frames carry `alternate_screen`, `mouse_mode` and `mouse_encoding` so the renderer can tell the cases apart.

- **The wheel respects its own units.** `onWheel` ignored `deltaMode` and mapped every event to a fixed `±scrollRows`. A trackpad reports a handful of *pixels* per frame, so one flick became hundreds of rows and fired a full-grid repaint per event, pinning the viewport to an end of the buffer while saturating the IPC channel. Pixel deltas now convert through the measured cell height, line and page deltas keep their own meaning, sub-row remainders accumulate so a slow drag still moves, and one scroll request is in flight at a time with an absolute jump superseding queued relative movement.

- **A scrollbar.** Draggable, sized from a new `scrollback_max` on the frame — vt100 exposes the scrollback *offset* but not the buffer's length, so `build_frame` probes it by asking for more than could exist and reading the clamp back. It is an overlay in the host's 8px padding, so it steals no column from the grid, and it only exists once there is history to reach.

- **Keyboard scrolling.** `Shift+PageUp` / `Shift+PageDown` page the viewport, `Shift+Home` / `Shift+End` jump to the ends. Bare `PageUp` still goes to the tty, because pagers and editors bind it themselves.

- **The host no longer drops the last frame of every burst.** `spawn_reader` set a dirty flag and emitted only when 8ms had elapsed — then blocked in `read()`. The final chunk of any burst sat unpainted until the program happened to write again, which is output that stops halfway through and completes when you press a key. Emission moved to a companion thread that wakes on the interval and flushes if the parser moved. Rate limiting cannot live inside a blocking read loop; that was the bug, not the interval.

- **The first prompt can no longer be lost.** Subscribing before spawning was meant to catch a prompt that arrives before `ptySpawn` resolves, but the frame handler drops anything whose id it does not recognise — and until the spawn call returns, it recognises nothing. Everything after that is a delta against rows the host already considers painted, so a dropped prompt would stay missing until something else rewrote its row. A refresh once the id is known closes the window.

- **The terminal takes focus.** There was no `focus()` call anywhere in `TerminalView` or `TerminalPanel`: keystrokes went nowhere until you clicked precisely on rendered text, and clicking the padding did nothing. The surface now takes focus when its tab comes to the front — detected from the box going from zero to sized, since inactive tabs are `hidden` — and when any part of it is clicked.

- **Scroll failures are visible.** `ptyScroll(...).catch(() => {})` swallowed every error, which is how "the terminal does not scroll" becomes undiagnosable. One warning per session now.

- **Theme system** — palette resolution moved onto an explicit `isDarkTheme` set. The old `resolved !== "light"` test called amber dark and handed CodeMirror its dark defaults on a cream background. A pre-paint script in `index.html` stamps `data-theme` from localStorage so the first frame is correct, and the provider no longer writes the store before the Tauri read resolves — otherwise a window with empty localStorage (a fresh profile, or the pop-out terminal) persisted "system" over the real preference in `settings.json` before it had ever been read. Storage access is wrapped throughout, since private mode makes it throw.

- **Tests** — `scroll.test.ts` (delta modes per `deltaMode`, key gating, thumb geometry round-trip), `wheel.test.ts` (mouse and arrow encoders), `tokens.test.ts` (theme tokens), and three host tests: `the_alternate_screen_has_no_scrollback_to_move` and `mouse_reporting_reaches_the_frame` pin the mechanism the wheel routing depends on, `scrollback_moves_the_visible_window` drives the viewport path end to end. 317 renderer tests and 22 host tests.

- **Version bump** — `0.4.0 → 0.5.0` across `package.json` / `Cargo.toml` / `tauri.conf.json` (+ `Cargo.lock`), enforced by `npm run check:version`.
