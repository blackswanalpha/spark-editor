# 0.8.0 — 2026-09-04

sparkEditor is now **sparkBook**, and the window opens four more kinds of document: pictures, an editor for them, an animation timeline, and PDFs.

See `CHANGELOG.md` for the full entry.

- **Pictures open as pictures.** A PNG, JPEG, GIF, WebP, BMP, ICO or AVIF opens in a viewer with pan, zoom, rotate, flip and a choice of three backdrops for judging transparency — not as a wall of mojibake, which is what reading bytes as UTF-8 text used to produce.

- **An image editor, one click away.** From the viewer, **Edit** hands the same pixels to a layered raster surface: move, rectangular select, brush, eraser, paint bucket, rectangle, ellipse, line, text, eyedropper and crop. Layers have opacity, one of sixteen blend modes, visibility, a lock, and reorder / duplicate / merge-down. Eight adjustments — brightness, contrast, saturation, hue, blur, grayscale, sepia, invert — preview live on the selected layer and bake into the pixels when you apply them. The canvas resizes, rotates, flips and crops. Save writes PNG, JPEG or WebP over the file you opened.

- **A brush that behaves.** A stroke is painted to a scratch surface and composited once when you let go, so a stroke that crosses itself does not darken at the crossing. Soft edges are one blur over the finished path rather than a gradient stamped at every step, which is what keeps the edge even along the whole stroke.

- **An animation builder.** Put rectangles, ellipses, text or images on a stage, set keyframes on a timeline, and scrub. Keyframes drag to retime, take one of seven easings, and appear automatically as you edit a property that is already animated. The scene is ordinary JSON in a `.sparkanim` file — diffable, hand-editable, and version-controllable — so undo, dirty state and save are the same ones every other document gets. **Export HTML** writes a single self-contained file that plays anywhere with no runtime.

- **A PDF reader.** Pages render as you scroll and the text stays selectable, so copying out of a PDF gives you the text rather than a picture of it. Thumbnails, bookmarks, page navigation, fit-width and fit-page, rotate, and a search that reports which pages hold your term and highlights it where it sits.

## Added

- **Binary documents.** A document now knows whether it holds text or bytes. Byte documents keep base64 and save through a new `write_file_base64` host command; switching such a document to a text surface is refused, because reinterpreting base64 as source code is never what was meant.
- **`New Image` and `New Animation`** in the command palette and the File menu — a blank 1280×800 canvas and a starter scene.
- **Session checkpoint.** The projects the app knows about and the windows that were on screen at quit are recorded by the Rust host rather than by whichever renderer happened to be last, so reopening a session lands on the same tabs exactly once no matter how many windows ask.

## Changed

- **Renamed to sparkBook** — product name, window title, package, crate, bundle identifier and every file header. The GitHub repository keeps its `spark-editor` name, so update endpoints and release links are unchanged.
- **The four new surfaces are code-split.** pdf.js is larger than the rest of the renderer; a markdown session no longer downloads or parses it.
- **One place decides how to read a file.** `src/shell/openDocument.ts` chooses between the text and byte host commands, and every open path — sidebar, recents, command palette, workspace restore — goes through it.
- **Undo in the image editor is its own stack.** A layer stack cannot be expressed as a diff over a string, so that surface keeps a 24-step document snapshot history and the Undo command routes to it. Every other surface is unchanged.

## Fixed

- **Restoring a session no longer corrupts an image tab.** Workspace restore read every remembered tab as UTF-8 text, so a reopened PNG or PDF came back as replacement characters and saving over it would have destroyed the file.
- **Flood fill's "already this colour" check never fired.** The packed target colour was signed while the pixel read back from the canvas was unsigned, so clicking the paint bucket on a region that already had the fill colour did the whole fill again and pushed a pointless undo step.
- **A new blank canvas saved zero bytes.** The editor only encoded its pixels after the first edit, so `Ctrl+S` before the first brush stroke wrote an empty file.
- **19 dead documentation links.** The rename swept the GitHub URLs in the README, the gitflow guide and the changelogs along with it, pointing them at a repository that does not exist.
